## Confirmed envelope-store / lifecycle compatibility finding — 07:22 UTC

The read-only Firestore export reported: `envelopes=0`, `signatureEnvelopes=256`, `documents=101`, `signatures=47`, `signatureEvents=410`, `signatureProfiles=6`. The Court evidence route identifies this candidate as a modern `signatureEnvelopes` record (`__collection=signatureEnvelopes`) and reports `NOT_HASH_CHAINED`. In `getRecoveryEnvelope`, that marker is assigned only after the Durable Object `envelopes` lookup and Firestore `envelopes` fallback miss and the Firestore `signatureEnvelopes` fallback succeeds. Thus this Court record is not present in either legacy `envelopes` lookup used by that recovery resolver.

This explains the split:
- Owner list and recovery evidence work because those routes explicitly scan both `envelopes` and `signatureEnvelopes`.
- The email-link signing loader/mutator and `finalizeEnvelope` in `drive-gateway/src/signing.mjs` read `ctx.meta.get("envelopes", id)`; they do not load the Firestore-only modern record. A successful recovery-list/evidence response is therefore not proof that the signing link or completion path can process this Court envelope.
- The existing emergency/completed-copy route likewise expects the legacy recovery lifecycle state. The modern `InProgress` record is not eligible and the routes return HTTP 409.
- `signatureDistributions` and `signaturePersonalCopies` are separate Durable Object metadata collections created by the post-completion distribution code. They are not part of the Firestore export above. No count/read compatibility proof was obtained for those collections.

The backup snapshot records 16 non-owner rows with synthetic `email-link-...` identities, `emailLinkStatus=Not issued`, `linkExists=false`, and `boundToDocument+signer=false`; opened/used/expiry remain UNKNOWN. The owner row's link fields are null/UNKNOWN. No bearer token or token hash was output. The 13 SIGNED states therefore conflict with the absence of an issued email-link record for those email-link identities; they are not independently validated by the 20 events (only `Owner Section Saved` and `Workflow Started`) or the zero signature records.

The production finalisation environment guard allows a TRIAL envelope on a production Worker only when an `externalReference` is resolved and verified to the same TRIAL source. The sanitized snapshot did not expose whether this Court record has an `externalReference`; no finalisation was attempted. This does not alter the primary blocker: the modern Firestore record is not loaded by the legacy signing/finalisation functions.

**Root-cause assessment:** confirmed dual-store/schema lifecycle gap for this Court record, not proof of deleted source data. #987 repaired read-only recovery discovery; it did not bridge modern `signatureEnvelopes` into signing-link validation, finalisation, or post-completion distribution. Fix forward requires a separately scoped, compatibility-tested lifecycle adapter; do not attempt a 23 Nov rollback.
